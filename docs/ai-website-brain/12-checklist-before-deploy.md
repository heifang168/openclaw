# Checklist Before Deploy

## Purpose

This document defines the checklist that must be followed before reporting a website task as complete.

## Basic Check

Before reporting completion, confirm:

- The instructed files were created or modified.
- No unrelated files were changed.
- No unnecessary files were added.
- No existing important files were deleted.
- Markdown files are readable if the task is documentation.
- Page files are valid if the task is frontend development.

## Documentation Task Checklist

For documentation tasks, confirm:

- Correct file path
- Complete content
- Clear Markdown format
- No self-created strategy
- No Skill created
- No frontend code changed
- GitHub commit created

## Frontend Page Task Checklist

For frontend page tasks, confirm:

- Page route is correct
- Page loads normally
- No 404 error
- No build error
- Desktop layout is normal
- Mobile layout is normal
- CTA buttons are visible
- CTA buttons link to the correct target
- Main copy follows the provided instruction
- No exaggerated claims are used
- Visual style matches high-end B2B industrial direction

## SEO Checklist

For important pages, confirm:

- SEO title exists
- Meta description exists
- Only one H1 is used
- H2 sections are clear
- Keywords are used naturally
- FAQ section exists where required
- Internal links are included where required

## Conversion Checklist

For important pages, confirm:

- Hero CTA exists
- Middle CTA exists where required
- Final CTA exists
- Contact or inquiry path is clear
- Inquiry form includes required fields where applicable
- CTA text is clear and B2B-oriented

## Visual Checklist

Confirm the page avoids:

- Cheap template style
- Overly colorful design
- Too much animation
- Weak CTA visibility
- Crowded layout
- Irrelevant images
- Low-quality images
- Poor mobile layout

Confirm the page follows:

- Industrial style
- Professional B2B layout
- Black, dark gray, yellow, white, and light gray color direction
- Clear typography
- Strong visual hierarchy
- Realistic product and application imagery where possible

## GitHub Checklist

Before reporting completion, confirm:

- Changes are committed to GitHub.
- Commit message is clear.
- Commit ID is available.
- Commit link is available.

## Vercel Checklist

After pushing to GitHub, confirm:

- Vercel deployment was triggered.
- Deployment status is Ready, Success, or Completed.
- No build error is shown.
- Website can be opened normally.

If Vercel fails, do not report the task as complete.

Report the error and wait for the next instruction.

## Report Format

After completion, report in this format:

Task completed.

Files changed:

- file path 1
- file path 2
- file path 3

GitHub commit:

- commit ID
- commit link

Vercel deployment:

- status
- deployment link if available

Validation:

- Documentation complete: yes or no
- Frontend changed: yes or no
- Build success: yes or no
- Errors: yes or no

## Final Rule

A task is complete only when:

1. The instructed files are correctly updated.
2. GitHub commit is created.
3. Vercel deployment does not fail.
4. The result matches the acceptance standard.
